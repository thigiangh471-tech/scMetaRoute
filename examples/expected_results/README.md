# Reference tutorial results

`cpu/` and `cuda/` hold small result tables generated by the complete six-step SLE example on Linux with Python 3.11, PyTorch 2.8.0 and the pinned dependencies. Both use one CPU thread; `cuda/` uses an RTX 3090 with the CUDA 12.8 wheel. They are scMetaRoute tutorial outputs, not comparator results or manuscript benchmark averages.

| File in each directory | Origin |
| --- | --- |
| `METRICS_RAW.tsv` | Ten metacell quality / post-fit annotation / cell-type DE metrics. |
| `DOWNSTREAM_METRICS.tsv` | Sixteen scores from neighborhood, clustering, co-expression and cross-donor annotation tasks. |
| `DE_SUMMARY.tsv` | Five eligible disease-by-cell-type contrasts; original versus compressed donor effects. |
| `TASK_STATUS.tsv` | Completed tasks and why significance-dependent disease ranking is not applicable. |
| `RUN_REPORT.json` | Effective fit settings, dimensions, seed and training/export time. |
| `PRODUCT_AUDIT.json` | Output shape, assigned-cell count and count-conservation checks. |

The subset has no reference DE genes passing Welch BH < 0.05. It still yields per-gene effect and BH tables when running the tutorial; those larger tables are generated locally rather than bundled. There are no significance-based disease ranking values to fill in for this example.

Floating-point libraries, device choice and clustering can affect the exact result of a new fit. Use these tables to inspect the expected schema and the scale of results; they are not universal numerical tolerances. `data/sle_5k_provenance.json` identifies the exact example input. CPU and GPU outputs are intentionally recorded separately.
